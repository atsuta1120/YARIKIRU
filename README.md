# YARIKIRU（やりきり）

「宣言するから、逃げられない。進捗が見えるから、続けられる。」をコンセプトにした、iOS向けの目標宣言・達成管理アプリです。本リポジトリは **SwiftUI製のiOSクライアント** のソースコードです。

## 概要

YARIKIRUは、その日に「やりきる」と決めた目標を登録し、達成状況を進捗バーで可視化するアプリです。単に完了/未完了を記録するだけでなく、目標ごとに難易度を設定して進捗への貢献度に差をつけたり、他ユーザーの目標がタイムラインで見える形になっていたりと、「宣言による有言実行」を後押しする設計になっています。

- **本リポジトリ（iOSクライアント）**: SwiftUI製。この README の対象です。
- **バックエンド（API）**: Python/Djangoで実装され、[atsuta1120/yarikiri_app](https://github.com/atsuta1120/yarikiri_app) で別リポジトリとして管理・公開されています。Render上にホスティングされたAPI（`https://yarikiri-app.onrender.com`）に対して本アプリが通信します。

## 開発目的・解決したい課題

一人で目標を立てても、誰にも見られていないと後回しにしたり、そもそも忘れてしまったりして続かない、という課題があります。この課題に対して、本アプリでは次の2つのアプローチを取っています。

1. **難易度に応じた重み付き進捗表示**: タスクの数だけをカウントすると、簡単な用事も大変な用事も同じ「1件」として扱われてしまい、進捗表示が実感と合わなくなります。難易度（小・中・大）に重みを持たせて進捗率を計算することで、「頑張り」がより実態に近い形で可視化されるようにしています。
2. **タイムラインによる緩やかなアカウンタビリティ**: 自分の目標をタグ別のタイムラインで他ユーザーに公開し、絵文字でリアクションし合える仕組みを用意することで、「誰かに見られている」という緩やかな強制力を持たせています。

## 主な機能

| 機能 | 概要 |
|---|---|
| 目標の登録・編集・削除 | タイトル・難易度（小/中/大）・タグ（カテゴリ）を指定して目標を管理 |
| 進捗の可視化 | 難易度の重み付けを反映した達成率をプログレスバーで表示 |
| タイムライン | タグごとに他ユーザーの目標を閲覧し、絵文字（🔥/👏/💪）でリアクション |
| 履歴 | 過去の日ごとの達成状況を一覧で確認 |
| 簡易ユーザー識別 | ログイン不要で、Cookieベースに「自分の投稿」を判定 |

## 使用技術

**iOSクライアント（本リポジトリ）**

- Swift 5 / SwiftUI
- Swift Concurrency（`async`/`await`）による非同期処理
- Observation framework（`@Observable`）を用いたMVVM構成の状態管理
- `URLSession` + `Codable` によるAPI通信（サードパーティの通信・状態管理ライブラリは未使用）
- 対応OS: iOS 17.6以上 / Xcode 26.2で動作確認済み

サードパーティ製ライブラリを使わず、Apple標準フレームワークのみで構成しているのは、依存を最小限に保ちつつ最新のSwift標準機能（Observation / Concurrency）を活用する構成を意図したためです。

**バックエンド（別リポジトリ）**

- Python / Django / SQLite
- ホスティング: Render
- 詳細は [atsuta1120/yarikiri_app](https://github.com/atsuta1120/yarikiri_app) を参照してください。

## 工夫した点

### 1. 難易度による重み付き進捗計算

- **課題**: 目標の件数だけで進捗率を出すと、簡単なタスクを大量にこなしただけで進捗が埋まってしまい、「頑張りの実感」と表示がズレる。
- **設計・実装**: `Goal` に `difficulty` と `weight` を持たせ、完了済み目標の `weight` 合計 ÷ 全目標の `weight` 合計で進捗率を算出する仕組みをHome画面のViewModelに実装（`HomeViewModel.recalculateProgress()`）。UI上にも「難易度が高い程進捗への貢献が大きくなります」という説明を明示。
- **価値**: 進捗バーが実際の負荷感に近い形で表示され、簡単なタスクの積み上げだけで達成感を水増しできない設計になっている。

### 2. タグ別タイムライン + リアクションによるアカウンタビリティ設計

- **課題**: 個人のTODO管理で完結すると、宣言による強制力が働きにくい。
- **設計・実装**: タグごとに他ユーザーの目標を横断的に閲覧できる `TimelineView` を用意し、絵文字リアクション（🔥/👏/💪）と閲覧数を表示するAPI連携を実装。`isMine` フラグで自分の投稿かどうかを判定し、UI上で区別。
- **価値**: 単なる個人用TODOアプリではなく、「見られている」ことを前提にした軽量なSNS的モチベーション設計を実現している。

### 3. サードパーティ非依存のシンプルな状態管理

- **課題**: 画面ごとに「読込中・エラー・データ取得済み」という3状態を扱う必要があり、外部ライブラリに頼ると依存が増えやすい。
- **設計・実装**: 各画面のViewModelをすべて `@Observable` + `async`/`await` のみで構成し、通信処理は `APIService` 一箇所にまとめて集約。
- **価値**: 依存ライブラリをゼロに保ったまま、Apple標準の最新機能で保守しやすいMVVM構成を実現している。

## 生成AIの活用について

本プロジェクトでは、実現したい機能・画面構成などの要件は自分で整理した上で、生成AI（Claude Code）に画面仕様・データ構造・実装コードの提案を依頼しました。生成された内容はそのまま採用するのではなく、提示されるたびにコードの内容を読んで理解し、動作確認を行った上で採用しています。設計自体もAIの提案に基づく部分が大きく、要件定義とレビュー・採用判断を自分が担う形で開発を進めました。
